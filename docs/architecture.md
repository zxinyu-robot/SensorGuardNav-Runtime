# 架构与状态机

## 数据边界

运行时每帧接收同步后的点云、scan matching 位姿增量、IMU航向增量、轮速位姿增量、安全
上下文及恢复证据。时间同步、外参标定和坐标变换由适配层负责；核心库只处理已经归一化的
数据契约。

输出 `RuntimeDecision`，包含：

- 当前和上一导航模式；
- LiDAR健康分数、故障类型和连续帧计数；
- 最大允许速度及是否必须停车；
- 建议的局部、全局或人工恢复动作；
- 状态转换原因和逐项证据。

## 决策分层

1. `detection` 只生成单帧质量和多源一致性证据。
2. `TrustArbiter` 通过EMA、窗口、滞回和连续帧确认形成稳定健康状态。
3. `SafetyEnvelope` 独立计算速度上限，避免“定位还能推算”被误解为“可以继续正常行驶”。
4. `RecoveryGate` 负责传感器重新接管条件。
5. `NavigationStateMachine` 只执行定义过的模式转换。
6. `telemetry` 保存低带宽、可回放的决策记录，不复制原始点云。

## 状态不变量

- `HEALTHY` 不能直接跳到恢复态；
- 单帧异常只能进入 `SUSPECT`；
- 失去有效障碍观测时必须请求 `SAFE_STOP`；
- 恢复必须经过连续健康确认；
- 多假设高度歧义时不得恢复单一位姿；
- `MANUAL_REQUIRED` 是终止态，需要上层显式复位运行时。

本实现是参考监督器，不替代硬件急停、功能安全控制器或机器人的最终速度限制。
